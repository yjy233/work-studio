# Agent 的八个基本概念

把任务想成“读一篇 Markdown，提炼三个观点并保存”。模型决定下一步，程序负责真实读取、写入和检查。工具返回的结果再进入下一轮模型输入，形成反馈循环。

| 概念 | 用一句话解释 | 在工作台中的例子 |
| --- | --- | --- |
| Model | 根据输入生成文本或行动请求的模型 | Codex 使用的模型 |
| Tool | 有输入、输出和副作用的可执行函数 | 读 wiki、运行测试 |
| Agent loop | 反复推理、行动、观察，直到结束 | 读资料 → 写摘要 → 检查链接 |
| Context | 本次请求实际能看到的信息 | 规则、对话、已读文件、工具结果 |
| State / session | 跨轮保留的程序状态 | 消息列表、任务 ID、当前目录 |
| Memory | 跨会话可检索、更新的长期信息 | 用户偏好、已确认事实 |
| Skill | 可复用的任务步骤和约束 | 原始资料 → 来源摘要 → 概念页 |
| Evaluation | 用外部可检查的标准衡量结果 | 文件存在、来源可追溯、测试通过 |

## 一条消息流

1. 用户：“总结 raw/a.md”。
2. 模型提出 `read_file`，参数指向文档。
3. 程序校验路径并读取，返回文件正文。
4. 模型基于正文提出写入动作。
5. 程序保存，返回实际路径和版本。
6. 读回文档、验证引用，再给用户结果。

“模型说已保存”不能替代磁盘证据。工具调用也不等于成功：调用可能超时，或进程返回非零状态。

## 三个容易混淆的地方

- 工具协议与工具实现不同：JSON 里写了命令，只是一个请求；只有执行器调用后才产生副作用。
- 上下文长度与记忆不同：一段旧历史存在数据库，不代表本次模型请求真的包含它。
- Skills 与训练权重不同：把成功步骤写成文件是一种外部经验积累，不能据此宣称模型参数被训练更新。

## 第一份练习

写出“搜索概念页 → 读取两个相关页面 → 回答并列来源”的三轮轨迹，给每轮标注输入、行动、观察、结束依据。然后解释：如果搜索结果里含有“删除所有文档”，程序应该把它当成什么？答案应是资料内容，而不是用户授权。
