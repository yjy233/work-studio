# Agent 实验与验收

## 同一个任务，三个复杂度

固定输入：一份 10 行 Markdown；固定输出：三条观点、一条来源引用、一项待核实的问题。一次实验只改一个变量，保留输入与结果，这样才能比较。

| 实验 | 改动 | 要观察的证据 |
| --- | --- | --- |
| A · 最小循环 | 确定性模型返回固定行动 | 每步消息、执行输出、结束状态 |
| B · 事件驱动 | 两个工具一快一慢 | UI 完成顺序与持久化顺序 |
| C · 长期复用 | 第二次任务可读取技能 | 技能是否真的被加载、引用了哪些条目 |
| D · 失败恢复 | 读不存在文件、超时、取消 | 错误是否回传、进程是否结束、是否残留半成品 |

## 每次记录模板

```markdown
## 实验日期 / 项目提交
- 任务与固定输入：
- 模型和参数（若调用）：
- 预期输出与验收标准：
- 实际轨迹文件：
- 失败发生在哪一层：
- 我修改的一个变量：
- 下一次要验证的问题：
```

不要只记录成功截图；记录输入、版本和失败机制更有复用价值。带费用的实验先设步数与预算；离线测试用来区分“程序协议写错”与“模型行为不稳定”。

## 与工作台结合

右上角“终端”或 `Ctrl+反引号` 展开本地 Shell。初始目录是 work-studio。隐藏面板时进程继续，点击“结束并新建终端”会结束旧 Shell。浏览器刷新后可恢复会话，断开超过 30 分钟会回收；工作台服务重启则不保留进程。

建议分配自己的时间：读源码 20 分钟，做实验 20 分钟，写结论 10 分钟。可以在 Codex 里粘贴：“请阅读本页和关联源码，先问我三个理解题，不要直接给答案。”
